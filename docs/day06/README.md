# Day 6｜從活動海報到服務資料

操作與程式見 [examples/day06](../../examples/day06/README.md)。

本篇新增的能力：用 Gemini 從圖片整理活動資料，保留欄位原文，經人工核對後交給 Day 5 的搜尋工具。

## 讀者可以觀察的三段結果

**模型擷取 → 人工核對 → 工具查詢。**

一般提示與欄位提示共用同張圖、模型、schema 與生成設定，每組一次。實際回覆、耗時與用量寫入 `verification.json`。人工改動另存在 `review.audit.json`，最後的工具結果在 `query.json`；原始輸出保留。

`counterexample.py` 另外示範「JSON 格式合法，但集合時間與預期不符」。這是合成單元測試，不是 Gemini 已發生的錯誤。真實海報是否出現類似情況，要讀該次兩組結果。

## 與 Day 5、7 的關係

Day 5 教模型使用 `search_local_events`；Day 6 整理該工具需要的資料。原 Day 5 載入器限定合成資料，因此 Day 6 使用自己的已核對目錄入口、重用搜尋邏輯，沒有修改歷史範例。

Day 7 再處理來源、更新與引用衝突。本篇 `updated_at` 只接受來源實際提供的時間；擷取與核對時間另外保存。

## 可重現範圍

自行提供可使用的海報與既有 Gemini 金鑰，依操作指南產生新的紀錄。圖片與人工核對檔原則上留在私人工作目錄；經作者確認可公開的來源及成果另行選取。本篇程式公開後，文章連到對應 commit；若作者有建立 tag，再使用實際 tag。
