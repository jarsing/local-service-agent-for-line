# Day 7｜來源更新與欄位複核

操作入口：[examples/day07/README.md](../../examples/day07/README.md)。

本篇延續 Day 6 的讀者提問：主辦更換海報，應按圖片雜湊建版，還是按欄位差異複核？本例把兩者分工，再加上容易漏掉的**穩定場次配對**。

## 本篇成果

舊圖引用 Day 6 真實核對結果，新圖由有標示的教學副本送入 Gemini；日期缺年份時，另外保存對應公告的引句。Python 比較欄位、安排複核，最後仍使用 Day 5 的搜尋工具查更新前後。

原始圖片、模型擷取、人工採用三種版本各自保存。網址相同不代表內容相同；圖片不同也不表示每個活動欄位都不同。Google 的圖片理解與 Structured Outputs 負責產生候選欄位，採用政策由本機程式與人工確認共同完成。

## 教學反例

`demo.py` 與測試使用明確標示的離線資料：檔案位元組改變但欄位未變、場次重新排序、引句或狀態改變、活動新增與消失、舊版複核檔套到新資料。案例與真正 Gemini 執行分開記錄。

## 和後篇的關係

Day 8 會把「使用者同意的到底是哪一個版本」接進操作確認。Day 7 保留穩定活動 ID、採用版本、來源和待核狀態，作為接點。本篇沒有部署、沒有改寫 Days 1～6，也沒有將新目錄直接替換正在服務的 LINE Bot。
