# Day 8｜一句「好」不夠：確認綁定具體操作

正式文章：待 2026-09-22 發表後補齊。

操作入口：[examples/day08/README.md](../../examples/day08/README.md)。

本篇將焦點由「資料版本」推進至「使用者同意」：當使用者在對話中說「好」，系統如何確保他同意的是特定版本、特定內容，且在有效時限內的操作？

## 本篇成果

1. **Google ADK 工具確認**：實作 `ToolContext.request_confirmation` 機制，在工具執行期間暫停、發出結構化確認請求，並在使用者回覆後恢復執行。
2. **應用層身分與版本防線**：在後端建立 `ConfirmationStore`，確認紀錄嚴格綁定使用者身分、Session、操作指紋（SHA-256）、目錄採用版本與過期時限。
3. **等待中換版防禦（教學反例）**：演練使用者看過舊時段（07:30~11:00）後，決定期間系統已切換至新版（08:00~11:00）；後端重新核對時拒絕舊確認（回傳 `version_changed`），並出示新版資訊，保留已輸入文字避免重打。
4. **離線驗證與小規格**：提供 25 項核心邏輯測試、9 項 ADK 流程整合與介接回歸測試與離線示範，全數通過離線測試（34 PASS）。
